# Managed series bridge (staged)

The public lobby code remains stable. Each engine series has a separate unique six-character transport/storage code and its own engine match ID. Existing engine event journals, snapshots, replay archives and Ranked settlement remain keyed by their existing engine identities. Do not expose engine codes as lobby invitations.

`persistManagedSeries` accepts a server-validated engine initialization and exactly two human membership-to-seat bindings. It persists engine state, events, receipts, capabilities, historical account association, presence and the lobby active-series pointer in the same D1 batch. Activation checks lobby version, host identity, live membership, both seat mappings and configuration structure. Any failed assertion rolls everything back. Duplicate start command IDs recover the original series reference; newly generated credentials must not be returned on a duplicate.

`requestManagedDeparture` creates a durable intent scoped to the current membership and series. Explicit requests require verified identity; expiry requires the server deadline to have elapsed. `resolveManagedDepartures` runs the internal FORFEIT_SERIES reducer command through the existing event store and invokes existing Ranked settlement/archive operations before clearing the lobby's series pointer and removing pending members. Completion revokes old seat controllers. A failed result/settlement leaves the current pointer and intent for recovery. The first accepted departure (timestamp then stable membership ID for ties) determines the forfeiting player; any additional pending departures are released after settlement. This tie policy is provisional and needs product approval for simultaneous expiry. Existing public CONCEDE still concedes a single game; FORFEIT_SERIES is not exposed as an API action.

The bridge is not a public cutover. It does not yet construct canonical engine players from persisted lobby deck snapshots, implement readiness/configuration commands, migrate legacy rooms, issue/recover new credentials or handle local Training. It accepts only online Casual/Ranked series; local Training requires a separate integration path preserving the same membership authority. The caller must allocate a fresh engine code, validate deck/roster snapshots and readiness and initialize the correct gameplay phase. A completed series is available through the existing archive; the old engine seat is no longer a live membership.

Before enabling the new API: route managed start/leave/expiry through the room coordinator, publish terminal state to eligible players before revocation, enforce managed-seat checks on HTTP, socket, resume and stale command paths, run scheduled expiry and completion recovery, reconcile legacy identities, add global application recovery/route guards, and test real D1/DO concurrency. The existing game routes still operate on legacy sessions. Migration 0018 adds the bridge tables/triggers; no backfill or deployment is included.
