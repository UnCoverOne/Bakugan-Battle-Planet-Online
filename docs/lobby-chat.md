# Persistent lobby communication (staged)

Migration 0020 adds one append-only sequence-ordered stream per persistent lobby, with per-membership admission and read cursors. Chat is independent of engine state, event versions, replay records, local Training checkpoints and series identities. A subsequent series does not clear chat. Access ends on explicit departure, expiry, pending forfeiture or lobby closure. A newly admitted opponent sees only messages from their admission onward; the existing member keeps their earlier history. Historical rows are retained but no closed-lobby history is exposed; a permanent retention/deletion policy is deferred.

POST /api/lobby/chat is gated by the same disabled persistent-lobby cutover flag, requires the verified account or guest membership, and refuses unresolved identity conflicts. history returns the latest 60 entries or the 60 before an exclusive cursor, plus the latest sequence and unread count; send takes a stable command ID and uses the existing 240-character normalization; read advances the cursor monotonically only to a visible message in that lobby. Server-derived names prevent client impersonation. Database guards reject Training user messages, expired/departing memberships, cross-room writes and more than 12 user messages per minute per member. A repeated send command cannot append a duplicate, and different content under the same ID conflicts.

System messages are generated by SQL triggers in the same transaction as lifecycle changes: lobby creation, joining, leaving, observed disconnection/reconnection, configuration changes, readiness, generic deck-selection updates, automatic AI assignment, series start/end and game results. The chat stream does not contain deck details, Ranked hidden roster information, raw game logs or card events. Connection changes are observed through chat polls; brief disconnections that nobody observes need not generate a message. The game's own event log remains separate. Training displays system messages only.

The application-wide LobbyChatProvider is stable across page navigation and scoped to the verified membership. It polls every 12 seconds when no panel is open and every three seconds while a panel is visible; it wakes on focus/reconnection. Requests are serialized and aborted on membership change. History loads in pages; unread state is shared by the lobby panel, gameplay drawer and Return to Lobby navigation indicator. Read acknowledgements occur at the latest visible message in a focused page, not merely when polling. Own sent messages do not count as unread. Drafts and retry IDs survive page navigation within a membership, not departure. The current gameplay drawer uses transitional styling; the responsive lobby redesign remains next.

Managed online game chat commands are fenced from the legacy engine path; legacy games remain unchanged with the gate disabled. The staged UI mounts the same panel in preparation, Ranked ban/select and BO3 intermission, and regular gameplay. No production migration or deployment.
